# Aggregate measurement boundaries

The shared histogram implementation is in `src/contracts/lib/measurements.ts`; metric names and millisecond bucket bounds remain those of TF-PS024-1.0.0. Storage is fixed size, capped at one billion samples/failures per producer. Quantiles are bucket upper bounds; overflow quantiles are unknown. A failed operation increments `failures` instead of adding a successful latency sample.

All duration clocks are monotonic. `issuance_http_ms` starts after blinding and ends at the complete issuer HTTP response (or transport failure), including any client gate wait, CONNECT and TLS setup. It excludes finalization and public verification. `token_acquisition_ms` includes blinding, HTTP, finalization and public verification. `protected_response_ms` includes CONNECT/TLS and the entire gateway response; the gateway sends `Connection: close`, so gateway connections are not reused.

Gateway `queue_wait_ms` starts immediately before flow acquisition and ends at its resolution. Only admitted acquisitions contribute latency samples; cancellation and refusal contribute failures. `verification_ms` covers the public signature verifier promise, before context and Redis. A rejected signature contributes a failure. `authorization_ms` starts on coordinator entry (complete HTTP headers available), includes admission, verification, snapshot/context and claim, and ends immediately before forwarding to the origin. It excludes origin latency and downstream response writes. Challenges and refusals count as unsuccessful authorizations.

`snapshot_rpc_ms` and `claim_rpc_ms` start immediately before the selected connection's EVALSHA call and finish when its bounded promise resolves or rejects. Readiness calls and local pool refusals are excluded. A Redis rejection such as ALREADY_SPENT is a successfully completed RPC, not a transport failure. An RPC failure increments failures; an ambiguous claim is never retried or refunded. No result payload or request metadata is retained by telemetry.

Workers sum bucket counts and failures; concurrent producer elapsed time is the maximum, never the sum. Client measurements arrive through REPORT and gateway measurements through its worker IPC and ordinary REPORT. The report viewer recomputes samples per second from these declared spans. Gateway spans cover ready-to-report lifetime, including challenge and issuance activity; they are not the client redemption-only throughput denominator.

Supervision stays enabled with one heartbeat per second per role and the unchanged three-second lease. Its activity and resource cost remain inside measurements; there is no unsafe unsupervised comparison.

Resources in report schemas 2 and 3 are **process** measurements: CPU user/system microseconds are deltas from probe creation to REPORT; `peak_rss_bytes` is Node's process-lifetime RSS highwater, including startup. It is not a container or whole-host peak. Gateway workers are separate rows with worker indexes; CPU deltas can be summed, but summing RSS highwaters is only a sum of individual peaks, not a simultaneous peak. Supervisor, controller, issuer, clients and origin have separate probes. Missing role reports yield absent measurements, never zero resource usage. The proxy and Redis have no process probes; the reported host memory limit is provenance, not utilization.

RPC outcomes separate failures, deadline expirations and uncertain responses (the server outcome of a failed RPC is unknown). Timeouts are a subset of failures; uncertainty includes failures and is not an additional operation count. Failed claims can remain spent. These bounded counters are reported even when no successful histogram sample exists.

Source equality covers authenticated HTTP requests in one immutable generation. Each worker keeps one HMAC tag, a mismatch latch and a bounded count. The supervisor supplies a fresh private generation key and compares both workers' tags; tags travel only over private IPC and never into control replies, logs or reports. Each request address exists only as an input to this observation. Two different singleton worker sources cannot imply equality. Missing addresses or exhausted observation capacity yield unknown; a known mismatch yields false. S02 uses a dedicated generation and needs fifteen authenticated requests (ten first spends plus five replay presentations), equality and independent origin counters. This establishes observed shared egress, not client identity or anonymity.

The socket cap proof is a single-worker component TLS listener test using its production limit of 64: fill the cap, require prompt closure of the extra socket, verify cleanup and obtain a fresh challenge afterwards. It bypasses the proxy only inside the loopback test fixture; the deployed S10 still exercises queue/active limits through the unchanged 64-tunnel proxy. It does not claim to have reached both workers' socket caps from deployed clients.

Report schema 3 adds explicit reset confirmation: a successful scenario cannot make the suite PASS after an unconfirmed shutdown. The state-transition label FENCED is not external process-exit evidence. See the contract changelog for immutable historical schemas and strict benchmark evidence requirements.
