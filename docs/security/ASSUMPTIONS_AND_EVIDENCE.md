# Security, privacy and evidence limits

Authorization uses the pinned RFC 9578 Type 2 implementation, issuer-only signing key, genuine context verification and one atomic Redis claim. See [protocol/contracts](../../src/contracts/README.md), [dependency review](DEPENDENCY_REVIEW.md) and [technical design](../implementation/TECHNICAL_DESIGN.md). A copied unused bearer token can win its first spend; the later holder loses. Claims can remain spent when origin delivery or its response is uncertain. No exactly-once delivery, rightful-holder identification, anti-Sybil property or absolute anonymity is claimed.

The trusted boundary includes the Linux host, controller, gateway and intact single-primary replay state. Redis and private-origin transport are plaintext on internal networks. Wall clocks must be trustworthy and non-regressing; recorded-highwater detection does not detect every unseen clock excursion or silent rollback. Services fail closed on dependency, lease or state uncertainty. Strong fencing/confirmed exit precedes replay-state discard and fresh-key reset; [reset tests](../implementation/RESET_RECOVERY.md) cover old spent and unused credentials. Schema 3 records explicit reset confirmation; a controller state label alone cannot justify PASS.

Privacy Pass blindness does not hide source, proxy visibility, timing or a small cohort. The proxy still sees CONNECT destinations. Generation-scoped gateway equality retains one private HMAC comparison tag per worker, a mismatch latch and bounded observations; only a global boolean/count is reported. Neither addresses nor tags enter reports/control replies. This demonstrates observed shared egress, not identity or an anonymity score. [Measurement definitions](../implementation/MEASUREMENTS.md) specify the observation and timing boundaries.

Retention evidence is executable: [S15](../lab/SCENARIOS_AND_REPORTS.md) inspects live writable sinks, logging, mounts, Redis diagnostics and host exposure after real traffic. The 13 November baseline and subsequent schema-2 security run passed retention; a separate S10 heartbeat loss made the latter overall INCONCLUSIVE. Inspection failure stays INCONCLUSIVE. Host swap, memory dumps, VM snapshots, forensic erasure and host/root compromise remain outside these checks. Quarantined cross-process test credentials stay in private pipes/controller memory; JavaScript strings cannot be reliably zeroed. Report writers and CI artifact collection enforce schema/evidence and privacy scans before publishing sanitized aggregate files.

Capacity evidence has two distinct scopes: deployed S10 stresses active/queue pressure through the unchanged proxy, while the loopback TLS component test fills the real 64-socket worker boundary, rejects an extra connection within a deadline and verifies cleanup/availability. The proxy's 64-total-tunnel ceiling prevents the ordinary deployed clients reaching both workers' socket caps. See [tests and scenarios](../lab/SCENARIOS_AND_REPORTS.md). No production limit or allowlist is weakened for measurement.

[Repeated benchmark](../lab/BENCHMARK.md) results include supervision and connection setup. Failed/incomplete trials are retained, metrics are aggregate-only, and a gain needs complete independent generations and comparable conditions. Per-process CPU deltas and lifetime RSS highwaters do not establish whole-host utilization or simultaneous container peaks. Fresh warmup generations warm host caches; measured processes start cold. A second physical host and venue rehearsal remain team-supplied actions in the [deployment runbook](../../infra/deploy/README.md).
