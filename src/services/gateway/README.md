# Gateway

`HttpsGateway.prepare(manifest, lease, coordinator, { key, cert })` accepts private in-memory TLS PEMs after checking the run/config binding, certificate hostname and matching private key. It requires a READY or ENABLED lease; READY alone cannot admit traffic. The implemented lifecycle host provides credentials privately, binds the configured frontend interface and enables workers after the all-worker lease barrier. See the [runtime/controller guide](../../../docs/implementation/GATEWAY_RUNTIME.md). The default image command still prints bootstrap metadata and exits.

Ingress uses TLS 1.3, exact configured SNI and HTTP/1.1. Clients offering ALPN must offer HTTP/1.1; an absent ALPN offer falls back to HTTP/1.1. TLS 1.2, missing/wrong SNI, HTTP/1.0 and h2-only offers are rejected. Every response closes its connection: **one request per TLS connection, no downstream keep-alive or pipelining**. Benchmark reports must include this extra TLS cost; the fixed-origin pool still reuses upstream connections.

Each worker tracks at most 64 accepted TCP connections, including incomplete handshakes. Absolute deadlines start at TCP acceptance: 2 seconds for TLS plus headers and 5 seconds for the whole request, including response completion. A trusted per-request liveness callback is captured by the coordinator and included in its flow permit, so monotonic checks before claims, at native origin send and at final write settlement supplement timers. Delayed timer callbacks cannot extend request authorization. Native parsing caps headers at 8192 bytes; the complete raw list reaches the coordinator's 32-field and duplicate checks. Special HTTP events (Expect/100-continue, upgrade, CONNECT and parser errors) close the connection rather than triggering automatic responses or tunnels. GET bodies are rejected; valid zero-body framing must actually complete before authorization begins.

The response sink holds the admitted flow until local TLS socket closure, checks lease/cancellation/deadline at finish and settlement, and never replaces a partial response. Upstream 502/504 use empty no-store responses with Content-Length: 0. `close()` is terminal and returns one cached promise waiting for listener closure, tracked raw/TLS sockets, handlers and coordinator cleanup. Cleanup failure rejects with a fixed error. This is a worker-local drain, not the complete all-worker/all-role FENCE barrier.

Tests generate temporary TLS credentials using OpenSSL (Git for Windows' OpenSSL when available), delete the temporary PEM files and never print keys. Linux integration passes the private material through Docker stdin to a single test file with test isolation disabled; that switch applies only to the test image. Real TLS/Redis/origin tests demonstrate a challenge, genuine blind issuance and two concurrent redemptions producing one origin arrival; rejected signatures/contexts/routes/framing produce no spends or origin arrivals. Linux regressions cover identical remote endpoints connected to different local addresses, plus a deliberately advanced request clock with disabled timers: expiry before claim spends nothing, and expiry before native origin send retains the committed spend without forwarding. Controlled native-write callback tests verify cancellation and late-completion cleanup; they are fault injection, not network-loss measurements. Production images exclude test code and credentials.

The worker-local request coordinator connects verification, bounded admission, atomic replay claims and fixed-origin transport. Tests include real blind issuance, Redis and an independently counted origin. The HTTPS serving process, private control helper and one/two-worker supervisor are implemented and tested. **Deployed issuer/client integration, Compose isolation and the complete cross-role reset barrier remain pending.**

`TokenVerifier.prepare(manifest)` copies and validates trusted configuration and imports only the issuer public key. `verify(wire, expectedEpoch)` checks exact Type 2 length, full key ID, public signature and configured challenge digest. It owns copies of incoming byte views before awaiting crypto. Rejections use fixed labels without reflecting credentials.

Success returns a `claim-candidate` with spend ID and epoch, not an authorization decision. The HTTP adapter must obtain `expectedEpoch` from a safe authoritative snapshot; the later atomic Redis claim must recheck current time/context before any forwarding. Repeating this component alone does not prevent replay. Do not log returned spend IDs or raw token data.

The coordinator uses `verifySignature(wire)` followed by `checkContext(receipt, snapshot.epoch)`, preserving signature-before-snapshot ordering. Receipts are frozen empty objects with private per-verifier WeakMap state, consumed once; they expose no token bytes and cannot transfer verification between instances. The original `verify(wire, epoch)` API still composes these stages for component consumers.

`parseAuthorization(request.rawHeaders)` accepts the complete flat raw header list, not Node's normalized header map. It bounds field count/Latin-1 octets before parsing, refuses duplicate Authorization fields and duplicate parameter names, processes quoted strings/escapes, and ignores syntactically valid unknown parameters. It tolerates at most eight empty list members. Decoded tokens must have canonical base64url and exactly the Type 2 wire length. An absent/unsupported authentication scheme requests a PrivateToken challenge; parsing a credential does not validate its signature.

`GatewayResponses.prepare(manifest).rejection(reason, freshSnapshotReply)` returns fixed JSON, `no-store` and byte-accurate content length. Every 401 requires a checked snapshot matching the configured run/key/digest/bounds and includes the shared challenge/public key. Missing/unsafe snapshot data produces 503 without a challenge. A 405 includes `Allow: GET`. Nothing reflects submitted credentials or creates clearance cookies. Before using this formatter, the future HTTP adapter must obtain a new authoritative snapshot and check its active supervision lease; the formatter does not establish freshness or run state itself.

The HTTPS listener and coordinator enforce transport and admission controls described below; these pure header helpers alone do not enforce them. Protocol references: [RFC 9577](https://www.rfc-editor.org/rfc/rfc9577.html) and [RFC 9110 authentication](https://www.rfc-editor.org/rfc/rfc9110.html#section-11).

`RequestCoordinator.prepare(manifest, preparedWorkerLease, readyReplayStore, openFixedOrigin)` verifies the run/config bindings, imports the key, subscribes to replay closure, and marks that worker READY only after preparation succeeds. It never enables workers or implements an all-worker barrier. Replay terminal closure immediately faults the lease and cancels work; origin/replay binding views expose public identifiers only. Preparation is for the fresh fenced run, not same-run recovery.

`handle(requestView, asyncResponseSink)` owns bounded header/metadata copies before waiting, validates authority/path/method/framing, acquires admission, parses authorization, verifies signature, obtains a snapshot, checks context, atomically claims, rechecks liveness and performs one fixed-origin attempt. Missing/duplicate Host or invalid generic headers get400; otherwise precedence is authority421, path404, method405, framing400. Host is the configured name case-insensitively, with optional `:443`; target is exactly `/resource`; GET bodies, TE/Expect/Upgrade and ambiguous/nonzero/noncanonical Content-Length are forbidden. These metadata checks supplement, not replace, the future native TLS/HTTP parser and body/socket/deadline enforcement. No upstream write occurs on signature/context/replay/epoch failure or uncertain claim. Every final401 obtains a fresh snapshot and challenge; unsafe/missing challenge state becomes503 without that header.

The sink receives a fixed response/internal upstream status and cancellation signal. Its promise must settle only when the actual downstream write or abort cleanup completes. Keep permits through this stage; partial/sink failure is never retried with another response. A canceled/fenced connection may close instead of delivering a503. Internal upstream502/504 outcomes still need contract-consistent public formatting in the HTTPS adapter. `close()` is terminal, returns the same promise under reentrancy, and waits for origin and admitted-flow drainage. Cleanup failure rejects with a fixed label; the host must not treat it as a strong FENCED acknowledgement. Rejected/unadmitted writes still need the listener's independent socket/write/request bounds.

Connected tests in the isolated Redis harness use real blind issuance and the actual verifier/store/origin: concurrent redemption yields one origin arrival; rejected/uncertain paths yield none; cancellation after commit keeps the token spent; a real epoch boundary rejects a stale candidate and supplies an epoch1 final challenge; idle replay loss cancels a claimed delayed-DNS operation. These exercise the worker pipeline with a test response sink. The public TLS ingress, issuer enrollment service, full controller lifecycle, two-worker orchestration and network topology are not yet integrated.

`WorkerLease.prepare(manifest, {worker_incarnation, supervisor_incarnation}, onClose)` creates one immutable PREPARED run. After actual key/replay readiness succeeds, the enclosing worker calls `markReady()`. `enable(grant)` installs the first three-second supervision lease; an exact repeated ENABLE may acknowledge but never renew it. `heartbeat(grant)` renews only an unexpired run with matching identities and increasing sequence/issuance/expiry. The core retains the supervisor's original monotonic expiry; delayed delivery never starts a fresh duration. It checks the existing expiry again after grant validation, so processing across the boundary cannot revive the run. Details of the private grant are in the [technical design](../../../docs/implementation/TECHNICAL_DESIGN.md); controller payloads remain unchanged.

`checkActive()` must guard admission, queue promotion and the immediate initiation of forwarding without an intervening await. Status is diagnostic, not proof of a live lease. Timers provide idle expiry; synchronous checks handle paused scheduling and expire-before-renewal. Clock faults, expiry, dependency loss or `requestClose(reason)` permanently latch closure and abort `signal` before notifying the caller. Hooks must connect that cancellation to queued/active work and pool/socket closure. `fence()` performs local stop only and remains CLOSING; there is no FENCED acknowledgement or instance reset in this helper. The serving host now supplies all-worker ENABLE, private bounded IPC and a gateway-local drain/kill barrier; the controller must still complete cross-role fresh-run teardown. Tests cover delayed/duplicate grants, stale timers, validation across expiry, reentrancy, clock/scheduler/cleanup faults and a real idle timer. The Linux image check verifies shared monotonic-clock origin using two actual child processes.

`FlowAdmission.prepare(manifest, workerLease)` binds the worker's flow pool to that exact run/configuration. `acquire(requestAbortSignal)` admits at most one active flow for B0 or two for B1, with FIFO16 and an original 100ms monotonic wait. Overflow/queue expiry returns `rejected/gateway-busy`; inactive/closed runs return `rejected/authorization-unavailable`; disconnected requests return internal `canceled`. It performs no crypto, claim or upstream work. The caller must bridge real request disconnect/deadline events to an AbortController and enforce separate socket/header/body limits.

An admitted result contains an immutable permit with `signal`, `checkActive()` and idempotent `release()`. Check the permit immediately after acquisition and after async stages; it may already have been canceled before the acquisition promise was consumed. Check again immediately before protected I/O with no intervening await. Cancellation aborts the signal but retains active capacity until the owner completes actual cleanup and releases in its finalization path. Releasing twice cannot create extra capacity. Do not equate a Redis timeout or downstream disconnect with completion of native crypto/upstream work. The HTTP integration must hold the permit until those operations settle or the process is terminated.

Lease closure terminally closes the admission pool; explicit `close()` cancels the detached queue and active permits and returns one shared promise waiting for all issued permits to be released. It does not close the lease by itself or prove a strong FENCE barrier. Internal queue-clock/scheduler faults additionally close the worker lease before invoking cancellation handlers. Status contains only aggregate active/queued counts and closure. Tests cover profile saturation, FIFO, expired heads, disconnect/timeout/promotion races, late timers, retained active slots, reentrant cancellation, clock/scheduler failures and a real queue timer.

`FixedOrigin.prepare(manifest, workerLease)` binds a private, bounded upstream pool to that run/configuration. Call `forwardAfterClaim(permit)` only after the future coordinator verifies and atomically spends the token. The transport cannot establish that authorization precondition itself. It accepts no caller URL/headers/body: only fixed GET to `protected-origin:8080/resource`, Host and gateway-generated run header. It never forwards client credentials, cookies or verification flags. A WeakSet refuses a second invocation with the same permit; failed claims/delivery are never refunded or retried.

Socket limits are one for B0/two for B1, including total/per-origin/free limits. Requests retain their transport slot through complete-body/request settlement and Agent reuse/closure transitions, with no hidden waiting queue. Free sockets use the pinned Node Agent's explicit 15s idle timeout, cleared on reuse; the server may advertise a shorter lifetime. The absolute 2s monotonic deadline covers DNS/connect/headers/body, with checks at actual connection/send and before returning success. Cancellation during delayed DNS prevents a late write. Success requires complete status 200 and at most 16 KiB wire bytes, with 8192-byte/32-field response-header bounds. The returned headers are freshly built no-store/octet-stream/content-length/nosniff. Reject upgrades, informational responses, redirects, truncated messages, oversized responses and other statuses without reflecting upstream detail. No automatic decompression occurs.

Upstream failures yield internal `{kind:'upstream-error',status:502|504}`; cancellation/closure/capacity have fixed internal outcomes. The HTTPS listener maps these upstream errors to empty 502/504 responses with no-store and Content-Length: 0; no new public wire-body label is introduced. `close()` terminally destroys active and idle sockets and waits for local jobs and sockets. Aborted attempts, including cleanup-hook failures, retain their slot until socket-close is observed. The transport never releases the flow permit and does not acknowledge a full gateway FENCE. The owner still needs final cleanup across crypto/Redis/upstream/downstream work before release.

Loopback HTTP component tests exercise real sockets, fixed headers, response stripping, exact/oversized/truncated bodies, upgrades/header bounds, whole-body timeout, delayed deadline callbacks, rapid keep-alive reuse, Agent-discarded sockets, stale idle timeout events, pool closure, delayed-DNS cancellation and throwing cleanup hooks. A trusted programmatic `OriginRuntime` seam redirects only the isolated tests to ephemeral loopback ports; no request/environment flag selects it, and test servers do not enter production images. These tests verify transport behavior, not the still-pending complete token-to-origin authorization flow. [Node 24 HTTP](https://nodejs.org/docs/latest-v24.x/api/http.html)

`REPLAY_SCRIPTS.snapshot` and `.claim` each expose immutable `{ source, sha1 }` values. Both sources share the same guard validation and derive constants from the frozen protocol. The controller must load these exact UTF-8 bytes before enabling a fresh run and put their hashes into the manifest **before computing its configuration digest**. Workers will use only `EVALSHA`; script loss must close the run, never trigger live reload. Bootstrap must separately compare every policy field with the trusted manifest, as specified in the [technical design](../../../docs/implementation/TECHNICAL_DESIGN.md).

Snapshot is read-only and returns authoritative Redis time after checking exact guard keys, hash fields/types, non-expiring policy/clock, run/key/configuration identity, canonical integers and consistent clock highwater. Claim repeats those checks atomically, refuses a candidate from another epoch, validates the spent-key name/representation and uses `SET NX PXAT` to select one winner. Spent records expire at epoch end plus the configured guard; a replay neither refreshes nor refunds them. Responses follow the frozen tagged-array ABI; the adapter validates them with the shared `parseSnapshotReply` / `parseClaimReply` helpers.

`openRedisReplayStore(manifest, trustedEndpoint, onFault)` prepares one worker's pool. The endpoint accepts host/port/ACL username/password as private trusted deployment data, never a URL or arbitrary client settings. No credentials are returned in status/errors. Preparation checks both manifest script hashes against the locally reviewed source, then validates every policy field, the exact initial clock, guard types/cardinality/TTLs, script availability and a valid snapshot on every connection. **All workers must finish this preparation while fenced, before any claim is possible.** This does not bootstrap or repair Redis, validate server administration settings, or establish the controller's lifecycle barrier.

The profile fixes pool capacity: one connection for B0 or two for B1 **per worker**, one awaited RPC per connection. Excess local calls return `{ kind: 'busy' }` immediately; the future bounded flow-admission layer owns waiting. Connections use pinned ioredis 6.0.0 with explicit RESP2, lazy startup, AUTH-only handshake, no INFO readiness/client metadata writes, no offline queue, retries, reconnects, resend, resubscribe or automatic pipelining. Connect and command deadlines are 1000 ms and 250 ms, with monotonic post-await checks as well as timers. Any loss/error, unsafe/malformed reply or uncertain outcome closes the entire local pool, destroys sockets and emits one fixed fault notification. The enclosing supervisor must use that notification to close the run across workers.

`store.snapshot()` returns a checked `{ kind: 'snapshot', reply, now_ms, epoch, start_ms, end_ms }` or `busy`/`unavailable`. Pass its epoch to the verifier and its raw checked reply to challenge formatting. `store.claim(verifierCandidate)` accepts only an internal verified candidate and returns `claimed`, fixed replay/epoch rejection, `busy` or `unavailable`; it derives expiry from trusted policy. A `claimed` result still requires the future worker's live lease/run-latch check before one fixed-origin attempt. `store.close()` is terminal and suppresses late callbacks; it is **not** a strong FENCE acknowledgement. The enclosing lifecycle layer must still abort/drain all active transports and flows. Never create a replacement adapter to recover a closed run with the same key.

An unsafe result, malformed reply, script error, timeout or ambiguous mutation must **terminally close the caller's run latch**. These scripts do not implement that latch, supervise leases or authorize forwarding. They never repair missing guards, and snapshot cannot persist closure because it is read-only. Redis Lua serializes execution but does not roll back writes after a runtime error. No uncertain claim may be retried or refunded. Safety assumes trustworthy non-regressing Redis/host time and no silent state rollback; the clock tests cover detected regressions against recorded highwater, not arbitrary unseen clock excursions.

Real Redis component tests require Docker and run separately from the Docker-free `check:g0` suite:

```powershell
npm.cmd run test:replay --prefix src/services/gateway
npm.cmd run test:redis-adapter --prefix src/services/gateway
```

The script harness starts a digest-pinned Redis 7.4.8 container with no host ports, external network or persistent data. It tests 20 concurrent claims, exact expiry, a real epoch transition, identity/encoding failures, guard corruption, recorded clock regression, malformed spent state, a deliberately discarded committed reply and missing scripts. The test-only administrative connection seeds/resets isolated fixtures. Script-internal ACL commands are `TYPE`, `PTTL`, `HLEN`, `HMGET`, `TIME`, `GET`, `PEXPIRETIME`, `HSET` and `SET`, in addition to `EVALSHA`. The adapter also requires AUTH and `SCRIPT EXISTS`; its readiness uses those bounded reads. [Redis scripting](https://redis.io/docs/latest/develop/programmability/eval-intro/) and [absolute expiry inspection](https://redis.io/docs/latest/commands/pexpiretime/) document these server behaviors.

The adapter harness builds the separate `redis-adapter-tests` Docker target and shares only the isolated Redis network namespace. It tests the actual production adapter with a restricted gateway ACL, concurrent claims, startup/live corruption, script loss, server pause, socket loss and no reconnect. A separate test-only transport seam deliberately discards the reply **after a real claim commit**; this is controlled fault injection, not a claim about arbitrary network packet loss. Unit tests cover bounded capacity, connect/command deadlines, malformed replies, post-deadline success, cross-connection closure and exception-safe cleanup. Test targets/fixtures do not enter the final runtime image.

Do not enable Redis/ioredis DEBUG logs, diagnostics-channel tracing/APM subscribers or Node instrumentation preloads in baseline service launches. Those mechanisms can capture EVALSHA command arguments despite the adapter's fixed error handling. The [retention design](../../../docs/implementation/TECHNICAL_DESIGN.md) requires review of actual deployment environment/launch commands.
